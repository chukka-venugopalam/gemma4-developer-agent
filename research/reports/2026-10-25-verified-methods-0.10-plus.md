# Methods with verifiable scores of 0.10 or more

Gemma 4 Developer Agent Competition. Compiled from web research in this session; the Kaggle pages could only be read as search-index copies (their own pages are JavaScript-only for my tools), and I have not run or re-scored anything.

## 0. Bottom line

1. **Yes, there are public methods with platform-recorded scores of 0.10 or more.** The best-documented one is the **Budget-Fit single agent**: a public Kaggle notebook records **0.18**, and two independent repositories document the same configuration in detail.
2. **The highest recorded public notebook score is 0.20** ("Gemma 4 SuperAgent Reproduction"), and **the top of the leaderboard is 0.24** (at least four teams). **I found no public description of how either is built**, so there is no proof of method at that level.
3. **This changes my earlier picture.** The best-documented 0.17–0.18 configuration runs **thinking ON** (budget 4,096), with 8 min / 28 calls / 80 turns and 8,192 output tokens. My S0 baseline (thinking off, 5 min / 50 calls / 3,072 tokens) rests on late-September evidence and has **no recorded score of its own**. My earlier report rated the thinking question as unresolved (§E.3 rank 3, D3); this evidence tilts it toward thinking on.
4. **"Proof" here means a platform-recorded score plus a public artifact, not a mathematical proof.** The same configuration is recorded at 0.18 in one place and 0.13 in another (8 vs 11 tasks of about 58), which is inside normal noise. Nothing I found isolates which component drives the score.
5. **Rule update:** Kaggle's overview text now says every agent in a submission must use the same base model and offers a $10,000 small-model bonus (E2B or E4B), and one third-party repo lists four allowed base models (31B, 12B, E4B, E2B). My earlier "only the 31B is allowed" came from a 2026-10-02 mirror and is out of date. S0 stays valid (it uses the 31B).

## 4. What the documented Budget-Fit method is

Both repositories (B) agree on the configuration:

| Setting | Value |
|---|---|
| Model, tuning | Gemma 4 31B (`gemma-4-31b-it-qat-w4a16-ct`), prompt only, no fine-tuning |
| Sampling | temperature 0.2, top-p 0.95 |
| Output tokens | **8,192** including reasoning |
| Thinking | **On**, budget **4,096**, thoughts retained |
| Per-task budget | **8 minutes, 28 tool calls, 80 turns** |
| Command / final-check limits | 240 s / 300 s |
| Tools | six of the nine; graph and similarity tools unused |
| Context | 32,768; compaction threshold 14,336 |

Prompt policy as the paper-track write-up describes it: restate the expected behaviour first; bounded localization (focused search, reads of at most 120 lines); **make a source edit early (by about tool call 12)**; at most one focused check and one repair attempt, never the full suite; scratch files in `/tmp`; submit deliberately; avoid unproductive exploration.

Local evidence (TheWayLost, Tier B, not leaderboard evidence): 20 paired tasks, 4,096 vs 6,000 thinking budget gave 10/20 vs 12/20 (not significant); on 55 tasks Budget-Fit v5 scored 28/55 against 26/55 for the original baseline; an earlier round of the same 20 tasks gave 13/20 for 4,096, so run-to-run variation is large.

## 5. What is not proven

- **No ablation.** Nothing separates the effect of thinking-on, the 8-minute / 28-call cap, the output size or the prompt rules.
- **Same configuration, different scores.** 0.18 and 0.13 are both recorded; an analysis notebook titled "Most-Run Public Config Averages 10/58" suggests about 0.17 on average, but I could only read its title.
- **Nothing is known about the 0.20–0.24 methods.**
- **Local-to-leaderboard transfer.** Local pass rates (51% on 55 tasks) are far above leaderboard scores (about 17%).
- **No proof that "Bounded Rescue", the 6,000 budget or any small model reaches 0.10.** I found no recorded small-model score at all.

## 6. What this changes for our candidate (inference, not proof)

| Setting | S0 (built, no score) | Budget-Fit (recorded 0.18) |
|---|---|---|
| Thinking | off | **on, budget 4,096** |
| Time / calls / turns | 5 min / 50 / 100 | **8 min / 28 / 80** |
| Output tokens | 3,072 | **8,192** |
| Command timeout | 300 s | 240 s |
| Prompt | notes sentence after every tool result; submit early and resubmit | restate contract; edit by call 12; one check and one repair; deliberate submit |

Plausible enabler (inference): thinking-on configurations became viable after the 2026-09-30 harness change, which keeps thoughts between tool calls and honours the thinking budget. The 8-minute cap implies a 16-hour worst case across 120 tasks, so those notebooks only worked because most tasks end well before the cap; they did finish and score.

The evidence-based next step is a separate candidate built from the Budget-Fit notebook as published, submitted on its own and compared with S0, rather than more tuning of S0. Any later change then goes in one at a time.

## 7. How to verify this yourself

```
# public leaderboard CSV (exact scores, entries, dates)
kaggle competitions leaderboard gemma-4-developer-agent --download

# public notebooks with their recorded scores, best first
kaggle kernels list --competition gemma-4-developer-agent --sort-by scoreDescending --page-size 50 --csv

# source and outputs of the Budget-Fit notebook; hash the shipped archive
kaggle kernels pull verracodeguacas/gemma-4-agent-budget-fit-single-agent -p budgetfit -m
kaggle kernels output verracodeguacas/gemma-4-agent-budget-fit-single-agent -p budgetfit_out
sha256sum budgetfit_out/*.zip
```

Flags follow the Kaggle CLI as described by third-party repositories; confirm with `--help`. On any notebook page, the version history shows each version's recorded score and the page header shows the best score and its version (one notebook I saw shows 0.08 for its latest version but 0.10 as its best). To prove a method yourself, unzip the shipped archive, compare it with the repository descriptions, then submit it once and expect ±3 tasks of noise.
